## 1. 目标与完成定义

**目标**：让 `CLAUDE.md §11` 的 5 条验收标准在真机上全部通过。

**完成定义（DoD）**：
1. 侧边栏能选会话、看消息、生成建议、填入/发送
2. 三态齐全（加载 / 空 / 错误），任何情况下不白屏、不显示堆栈
3. 重复点击不会重复发送
4. 全部接口响应严格走 §5 信封
5. 未引入 `CLAUDE.md §2` 之外的依赖

**非目标（本次不做）**：自动发送、多账号、云端部署、微信 4.x、RAG/知识库/插件/搜索、打包分发。

## 3. 每个任务的详细规格

### T0 — 文档对齐与废弃清理 ⚠️ 需你确认

- **涉及文件**：删 `package.json`、`web/`、`src-tauri/`、`backend/launcher.py`、`docs/验证报告.md` 外的临时日志；改 `README.md`；改 `CLAUDE.md §10`（规范文档改动需你点头）
- **风险**：删除不可逆；`web/` 是唯一"能立刻用浏览器看 UI"的产物，删了就只能跑 PySide6
- **回滚**：删除前先 `git` 提交或整目录压缩备份到 `_backup/`

### T1 — V1 骨架与跳转

| 项 | 内容 |
|---|---|
| 改动 | 新增 `desktop/views/main_view.py`；改 `desktop/window.py`（注册视图、`main_requested` → `show_view(VIEW_MAIN)`）；改 `desktop/app.py` |
| 逻辑 | 进入 V1 时并发拉 `GET /api/sessions` + `GET /api/messages`（`who` 取 `data.current`，为 null 则取首个会话） |
| 验收 | 点 V0 的「仍以演示模式进入」→ 切到 V1 且会话/消息自动加载 |
| 风险 | 无焦点窗口下 `QStackedWidget` 切换无副作用，低风险 |
| 回滚 | 删除视图文件，window 恢复只注册 V0 |

### T2 — 会话区

| 元素（PRD §3.2） | 数据来源 |
|---|---|
| `listSessions` | `GET /api/sessions` → `sessions[].name/.isnew/.time/.content` |
| `btnRefreshSession` | 重新请求 |
| 空态 `lblSessionEmpty` | `sessions` 为空时显示"暂无会话" |

- **验收**：真实返回 4 个会话，选中项高亮，`isnew` 显示红点；断网时显示错误态而非空白
- **风险**：`name` 可能为 null → 兜底 `(未知会话)`
- **回滚**：独立 widget，可单独摘除

### T3 — 消息区

- 按 `type` 渲染 5 种气泡：`friend` 左、`self` 右、`sys/time/recall` 居中灰小字
- 三态：加载中（"加载中"）、空态（"暂无消息"）、错误（`1001`/`2001` → toast）
- **验收**：`GET /api/messages?who=张三&limit=60` 返回 5 条，气泡左右对齐正确，自动滚到底
- **风险**：`content` 长文本需 `setWordWrap`；切换会话时未清空旧列表
- **回滚**：同上

### T4 — 回复区（核心闭环）+ 防抖

| 元素 | 接口 | 关键约束 |
|---|---|---|
| `inputInstruction` | — | 可空 |
| `btnGenerate` | `POST /api/reply {who, instruction, messages:null}` | 请求中禁用按钮，文案"生成中" |
| `editReply` | — | 可编辑 |
| `lblSource` | `data.source` | `rule` 时标注"（规则兜底）" |
| `btnFill` / `btnSend` | `/api/fill` `/api/send` | 文本为空时禁用；**请求中禁用（防重复发送）** |
| `lblToast` | — | 2.6s 自动消失，非模态（不抢焦点） |

- **验收**：生成→改文本→填入→发送 全链路走通；发送后 800ms 刷新消息列表并出现自己发的消息
- **风险**：焦点铁律——toast 不能用 `QMessageBox`
- **回滚**：按钮级功能，可单独禁用

### T5 — 开关与 WS

- `btnDock` ↔ `POST /api/dock`；`btnListen` ↔ `POST /api/listen`；开关状态取自 `GET /api/status` 的 `docking` / `listen`
- 监听开启 → 连 `WS /ws/messages`；断开自动重连（5s × 3 次），仍失败则关闭开关并提示
- **验收**：开关状态与后端一致；WS 收到帧时追加气泡（当前会话）或红点（其他会话）
- **风险**：WS 需 `websockets` 依赖 —— **`CLAUDE.md §2` 未列该依赖**，方案：用 `QWebSocket`（PySide6 自带，**不新增依赖**）
- **回滚**：监听默认关闭，开关可独立禁用

### T6 — Toast 与错误码收口

- 实现 PRD §5 错误码 → 文案映射表（1000/1001/2001/3001/4001/5000 + 网络异常 + `degraded`）
- **验收**：逐个错误码触发，确认文案正确、颜色正确、不弹模态框

### T7 — 修复重复发送（验证报告 B7）

| 层 | 措施 |
|---|---|
| 前端 | 请求中禁用 `btnSend` / `btnFill` / `btnGenerate`（T4 已含） |
| 后端 | 3 秒内相同 `{who, text}` 直接返回上次结果（**需先写入 `CLAUDE.md §4` 再实现**） |

- **验收**：连续两次 `POST /api/send` 相同内容 → 第二次返回 `code=0` 但实际只发一次（后端计数校验）
- **风险**：真实微信下"用户确实想连发两条相同内容"会被拦 3 秒 → 接受（MVP 优先防误触）
- **回滚**：后端改动集中在一个装饰器，可整体摘除

### T8 — 完整验证

- 重跑 `_verify_e2e.py flow + boundary`，补 V1 的离屏渲染截图（成功态 / 空态 / 错误态各一张）
- **验收**：B7 转 PASS，V1 三态齐全

### T9 — README 重写

- 改为：PySide6 + FastAPI + SQLite 流程；启动命令 `python backend/server.py` + `python desktop/app.py`；环境变量以 `CLAUDE.md §9` 为准（DeepSeek 默认值）

### T10（可选）— V2 / V3

- 顺序：**先改规范 → 再实现后端 → 最后开发页面**
